## 1. Что это за продукт

Сервис финансового анализа для продавцов на Wildberries и Ozon — как FinTablo/Sellerboard/MPStats, но под нашу услугу. Берёт данные продаж (через API маркетплейсов **или** загрузку CSV из кабинета), приводит WB и Ozon к единой схеме и показывает в веб-дашборде:

- **Воронку денег**: реализация → возвраты → удержания МП → к выплате → (с себестоимостью) чистая прибыль.
- **Автоматический анализ**: где теряются деньги, убыточные товары, мёртвый сток, ABC-классы, юнит-экономика каналов, ДРР, концентрация выручки, динамика по месяцам.
- **Разрезы**: сегменты одним кликом, сквозная группировка раздел → подкатегория → товар, карточка товара («паспорт»).
- **Графику**, чтобы за 20 секунд было понятно, а не «полотно на 4500 строк».

Многоклиентность: один сервис обслуживает несколько продавцов, данные каждого изолированы по `client_id`.

## 2. Этапы работы

### Этап 1. Разбор задачи и архитектура
Проанализировали референс (статья + скриншот FinTablo/МП), определили пайплайн: **сбор → нормализация → хранение → аналитика → дашборд**. Договорились делать сразу оба маркетплеса под продажу услуги клиентам.

### Этап 2. Коннекторы к API маркетплейсов
- **Wildberries**: клиент к отчёту реализации, пагинация, обработка лимитов (429 + Retry-After).
- **Ozon**: клиент к Seller API (финансовые транзакции), пагинация по страницам.

### Этап 3. Единая схема и хранилище
Единая таблица операций (реализация, возвраты, комиссия, логистика, хранение, продвижение, штрафы, прочее, к выплате) с привязкой к клиенту и маркетплейсу. Идемпотентный upsert — повторный синк не задваивает данные.

### Этап 4. Нормализация WB и Ozon
Маппинг сырых ответов обоих API в единую схему. Ozon: разбор «услуг» по ключевым словам (логистика/хранение/продвижение), корректное распределение мульти-товарных операций.

### Этап 5. Аналитика
Модуль метрик (воронка, удержания, по товарам, динамика, план-факт) + модуль автоматических выводов (ABC, убыточные, мёртвый сток, каналы, ДРР, концентрация, MoM).

### Этап 6. Дашборд (FastAPI + веб-фронт)
Веб-интерфейс с фильтрами, вкладками (Анализ, Обзор, Товары, Возвраты, Контроль, Загрузка), графиками и экспортом в CSV.

### Этап 7. Загрузка CSV из кабинетов
Отдельная вкладка: загрузка выгрузки из кабинета ВБ/Ozon с **автоматической починкой** — кодировка (cp1251/UTF-8), разделители (`;`/`,`), русские числа («1 234,56 ₽»), даты, синонимы заголовков. Строки с ошибками можно поправить вручную и импортировать повторно; загрузку можно откатить.

### Этап 8. Ревью и исправления безопасности/корректности
Прогнали код через несколько ревью-агентов и закрыли: XSS, CSV-инъекции в экспорте, ошибка 500 на плане, потеря SKU в мульти-товарных операциях Ozon, тихая остановка пагинации, чувствительность к пробелам в типах документов WB, гонка при обновлении данных и др.

### Этап 9. Реальный финансовый анализ (не «список 4500 строк»)
По вашему запросу «где анализ?»: добавили подсветку убыточных позиций, ABC, юнит-экономику каналов, разбор возвратов в рублях **и** процентах, рекомендации «что делать» по каждой проблемной позиции.

### Этап 10. Группировка и карточка товара
Сквозная группировка раздел → подкатегория → товар, сегменты-фильтры, паспорт товара с полной раскладкой «от продажи до выплаты».

### Этап 11. Себестоимость → чистая прибыль
Отдельная загрузка файла себестоимости. После неё весь анализ (KPI, ABC, «где теряются деньги», карточки) пересчитывается по **чистой прибыли** (`к выплате − себестоимость проданного`), а не по обороту. Показывается покрытие: для скольких SKU нашлась себестоимость.

### Этап 12. Дизайн
Установили и применили дизайн-скилл Emil Kowalski (`emil-design-eng`): собственные кривые анимации, GPU-переходы, «одно яркое место» (герой-KPI), stagger-каскад карточек, `prefers-reduced-motion`.

### Этап 13. Мобильная версия
Исправили телефон: контент вперёд (а не форма фильтров), KPI по 2 в ряд с широкой плиткой прибыли, нулевой горизонтальный скролл. Проверено на 390px и 1360px в реальном браузере.

### Этап 14. Сведение основного приложения и витрины
Перенесли в серверное приложение всё, что было только в браузерной витрине: сегменты, вложенную группировку, карточку товара, поток рубля, гистограмму рентабельности, загрузку себестоимости. Теперь «продукт для продажи» и «то, что показываем» — одно и то же.

### Этап 15. Миграция WB на новый Finance API (до отключения 15.07.2026)
Старый эндпоинт ВБ (`reportDetailByPeriod`) отключается 15 июля 2026. Реализовали замену — новый `POST /api/finance/v1/sales-reports/detailed` на `finance-api.wildberries.ru`. Схему взяли из **официальной OpenAPI-спецификации ВБ** (не догадки). Старый эндпоинт оставили как запасной (`--wb-api statistics`).

### Этап 16. Сверка с кабинетом
После каждого синка пайплайн печатает помесячные итоги по каждому каналу (реализация / возвраты / расходы МП / к выплате) — сравниваете глазами с кабинетом, чтобы убедиться, что маппинг верный.

## 3. Технический стек

### Бэкенд
| Технология | Назначение |
|---|---|
| **Python 3.11** | основной язык |
| **FastAPI** | веб-API дашборда |
| **Uvicorn** | ASGI-сервер |
| **httpx** | HTTP-клиент к API WB и Ozon |
| **SQLite** | хранилище (единая таблица операций, планы, загрузки, себестоимость) |
| **Pydantic** | валидация входных данных API |
| **python-multipart** | приём загружаемых файлов |

### Фронтенд
| Технология | Назначение |
|---|---|
| **HTML + CSS (vanilla)** | вёрстка, тёмная/светлая тема, адаптив |
| **JavaScript (vanilla, без фреймворков)** | вся интерактивность: фильтры, вкладки, графики, группировки, карточки, загрузки |
| **SVG/CSS-графики собственной сборки** | столбики, поток рубля, гистограммы (без внешних библиотек) |
| **Дизайн-принципы Emil Kowalski** | анимации, типографика, motion |

### Интеграции с маркетплейсами
| API | Метод |

| **Ozon Seller API** | `POST /v3/finance/transaction/list` |

| **pytest** | 105 автотестов (нормализация, метрики, коннекторы, API, загрузки, себестоимость, пайплайн) |

### Что нужно от клиента для запуска в бою
1. **API-ключи** одного реального клиента:
   - Wildberries — токен **с категорией «Финансы»** (личный кабинет → Настройки → Доступ к API).
   - Ozon — `Client-Id` и `Api-Key` (Настройки → API-ключи).
2. Вписать их в `clients.json`.
3. Прогнать пробный месяц:
   ```
   python -m etl.pipeline --client <имя> --date-from 2026-06-01 --date-to 2026-06-30
   ```
4. Сверить напечатанные итоги с кабинетом. Если не сойдётся — прислать одну сырую строку ответа API, поправим маппинг.

### Известные ограничения (осознанные)
- Дашборд без авторизации — рассчитан на разворачивание отдельным экземпляром на клиента. При нескольких клиентах на одном инстансе нужно добавить токен-авторизацию.
- В новом WB Finance-отчёте нет «продвижения в рублях» — ДРР берётся из рекламного API или из CSV.
- SQLite подходит для одного/нескольких продавцов; для большой мультитенантности — переход на PostgreSQL (схема переносится почти как есть).
