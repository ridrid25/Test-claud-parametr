# Протокол перезаливки TikTok (проверен 04.10.2026: 0 → 487 просмотров)

Случай: ролик публиковался раньше (на этом или другом аккаунте) и
новая копия получает 0 просмотров. Причина: TikTok сверяет отпечаток
видеоряда и душит дубликаты. Протокол:

1. Открыть старый пост → сохранить его звук в избранное (пластинка
   внизу поста → флажок). Только потом удалять.
2. Удалить старый пост (или «в архив» / «видно только мне» —
   при нуле просмотров терять нечего, удаление чище).
3. Взять ИСХОДНИК из генератора/записей — никогда не файл,
   скачанный из TikTok (имя вида «аккаунт_дата», 576×1024, с
   метками платформы).
4. Сдвинуть отпечаток. СНАЧАЛА проверить, где начинается речь
   (silencedetect): если в начале есть пауза — подрезать первые
   0.5–1.0 с (и проверить, что хук-титр остался на первом кадре);
   если речь с нулевой секунды — начало НЕ резать, вместо этого
   зум кадра 4% (scale 1124:1998 + crop 1080:1920, титры по центру
   не страдают) и срезать тихий хвост. Если исходник меньше
   1080×1920 — заодно поднять до 1080×1920 (lanczos + лёгкий
   unsharp). Звук не трогать.
5. Загрузить через «+»: звук из избранного (громкость музыки ~треть,
   озвучку не перекрывать), НОВОЕ описание, 3 нишевых + 1 трендовый
   хэштег, галочка «Контент создан ИИ».
6. Темп: 1 ролик в день, следующий — только после результата
   предыдущего. Смотреть долю досмотра (для 10 с хорошо 70%+),
   а не только просмотры.

Правила профилактики: один файл = один аккаунт (на второй —
пересборка с другим хуком/озвучкой, не копия); исходники из
генератора в 1080×1920; серия нулей подряд = стоп и пауза, а не
«зальём ещё».

Команда сдвига отпечатка (из конвейера):
ffmpeg -ss 0.7 -i IN.mp4 -c:v libx264 -crf 17 -preset slow \
  -c:a aac -b:a 192k -movflags +faststart OUT.mp4
Для 720p-исходника добавить перед кодеком:
  -vf "scale=1080:1920:flags=lanczos,unsharp=5:5:0.35:5:5:0.0"
